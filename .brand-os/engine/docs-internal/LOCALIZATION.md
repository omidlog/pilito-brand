# Localization

English is the base language. The portal builds `en` by default plus the optional `fa` (right to left) and `tr` locales. Interview prompts are written in English with `fa` and `tr` translations as locale data; a missing translation falls back to English. The help text follows the same rule: `why_it_matters` and `examples` stay English in each question, and `why_it_matters_i18n` / `examples_i18n` hold the fa and tr versions (source: `packages/brand-core/src/content/question-help-i18n.ts`). Every example keeps its `EXAMPLE ONLY:` marker in every language, and a choice or boolean example stays the literal option value. `brand:validate` checks drift in the prompt, `why_it_matters` and `examples` for all three locales; a bank written before the fa/tr help text existed is still valid (one warning), and `npm run brand:migrate` refreshes the question text from the template without touching answers. A brand opts into locales with `brand:init --languages en,fa,tr`. Official brand sentences are not auto-translated.

Approved translations, when a human writes them, belong in `brand/translations/<locale>/<field-id>.md` with `status: approved` and the approver's name. Until that file exists, the English source remains the only official wording and the other locales reuse it for layout. Search stemming is English-only in this version.
