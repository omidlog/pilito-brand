# وصل کردن یک دستیار هوش مصنوعی به برند شما (راهنمای مالک)

زبان‌های دیگر: [English](AGENT_ONBOARDING.md) · [Türkçe](AGENT_ONBOARDING.tr.md)

این راهنما برای مالک برند است. لازم نیست برنامه‌نویسی بلد باشید. هر دستور را به ترتیب در ترمینال کپی کنید. در پایان،
یک دستیار هوش مصنوعی (مثلاً Claude Code) فقط می‌تواند واقعیت‌های **تأییدشدهٔ** برند شما را **بخواند**، نه بیشتر.
هر وقت بخواهید می‌توانید آن را خاموش کنید.

دستورهای Brand OS در این صفحه به‌صورت خودکار آزمایش می‌شوند (`tests/fresh-agent-setup.test.ts`)؛ گام‌های `claude mcp` و `read -rs`
دستورهای Claude Code و پوسته‌اند و آزمون آن‌ها را اجرا نمی‌کند. مرجع فنی:
[AI_CONNECTORS.md](AI_CONNECTORS.md).

## چه چیزی می‌گیرید و چه چیزی نه

- دستیار فقط واقعیت‌های **تأییدشده** را می‌خواند، و فقط بخشی از برند که «پروفایل» آن اجازه می‌دهد.
- دستیار **نمی‌تواند** چیزی را تأیید یا منتشر کند، واقعیت‌ها را تغییر دهد، کلید بسازد، یا مقادیر محرمانه (پول، بودجه، یادداشت خصوصی) را ببیند.
- همه‌چیز روی کامپیوتر خود شما اجرا می‌شود. ورود از طریق وب‌سایت و سرور ابری وجود ندارد. Brand Studio فقط برای دیدن است؛
  نمی‌تواند کلید بسازد یا دستیار وصل کند.
- اتصال آنلاین (میزبانی‌شده) ساخته نشده است. ببینید: [AGENT_ONBOARDING_HOSTED.md](AGENT_ONBOARDING_HOSTED.md).

## واژه‌ها

- **ترمینال**: پنجره‌ای که در آن دستور تایپ می‌کنید (macOS و Linux: برنامهٔ Terminal؛ Windows: ‏WSL یا Git Bash).
- **پوشهٔ برند**: پوشهٔ مخزن برند شما روی کامپیوترتان.
- **رمز تأیید (approval secret)**: یک فایل رمز خصوصی در `brand/.private/approval-secret`. ثابت می‌کند که *شما*، مالک، این کار را می‌کنید. هرگز آن را به کسی ندهید.
- **توکن دستیار (agent token)**: کلید یک دستیار. با `bos_at_` شروع می‌شود و فقط یک بار نشان داده می‌شود. مثل رمز عبور با آن رفتار کنید.
- **پروفایل**: آنچه توکن اجازهٔ خواندنش را دارد؛ مثلاً `design` (ظاهر و لحن برند) یا `content-read` (پست‌ها و برنامهٔ محتوا).

## پیش از شروع (یک بار)

۱. ‏Node.js نسخهٔ ۲۲ یا بالاتر و Claude Code نصب باشند.

۲. ترمینال را **در پوشهٔ برند** باز کنید و ابزارها را نصب کنید:

<div dir="ltr">

```sh
npm install
```

</div>

## گام ۱. ساختن رمز تأیید (یک بار)

<div dir="ltr">

```sh
npm run -s brand:doctor -- --create-approval-secret
```

</div>

باید این پیام را ببینید: `Approval secret is at brand/.private/approval-secret`. خود رمز هرگز چاپ نمی‌شود. اگر فایل از قبل
باشد، دست نمی‌خورد. ممکن است doctor موارد دیگری را هم برای درست کردن نشان دهد؛ برای این راهنما فقط رمز تأیید مهم است.

## گام ۲. ساختن توکن برای یک دستیار

کوچک‌ترین پروفایلی را انتخاب کنید که برای کار کافی است. بیشتر کارهای تصویری `design` می‌خواهند؛ پست‌ها `content-read`.

<div dir="ltr">

```sh
npm run -s brand:agent-token -- issue --profile design --label "claude-code design" < brand/.private/approval-secret
```

</div>

بخش `< brand/.private/approval-secret` رمز شما را بدون تایپ کردن و بدون نمایش به دستور می‌دهد. آخرین خطی که چاپ
می‌شود توکن است (`bos_at_…`). همین حالا کپی‌اش کنید؛ فقط یک بار نشان داده می‌شود. آن را در چت، ایمیل، پرامپت یا هیچ
فایلی در مخزن نگذارید.

## گام ۳. وصل کردن دستیار (Claude Code)

این سه خط را در پوشهٔ برند اجرا کنید. خط اول منتظر می‌ماند تا توکن را بچسبانید؛ هنگام چسباندن چیزی دیده نمی‌شود. بعد Enter بزنید.

<div dir="ltr">

```sh
read -rs BOS_TOKEN
claude mcp add brand-os --scope local -e BRAND_OS_AGENT_TOKEN="$BOS_TOKEN" -- npm run -s mcp:serve
unset BOS_TOKEN
```

</div>

این کار توکن را فقط در تنظیمات خود Claude Code و فقط برای همین پوشه ذخیره می‌کند (`--scope local`). در مخزن نوشته
نمی‌شود. هرگز توکن را در فایل `.mcp.json` که در مخزن ثبت می‌شود نگذارید.

## گام ۴. بررسی اینکه کار می‌کند

بررسی سریع در ترمینال (اختیاری)؛ باز هم وقتی خواست، توکن را بچسبانید:

<div dir="ltr">

```sh
read -rs BOS_TOKEN
BRAND_OS_AGENT_TOKEN="$BOS_TOKEN" npm run -s brand:query -- --tool get_brand_status
unset BOS_TOKEN
```

</div>

باید `"status": "approved"` را ببینید. سپس در Claude Code:

۱. دستور `claude mcp list` را اجرا کنید. `brand-os` باید وصل (connected) باشد.

۲. ‏Claude Code را در پوشهٔ برند باز کنید و بپرسید: *«با ابزار get_brand_status از brand-os وضعیت را بگو.»*

۳. یک کار واقعی بخواهید، مثلاً *«ده پست اینستاگرام برای این برند بساز.»* دستیار باید یک بار `task_context` را صدا بزند و فقط دربارهٔ واقعیت‌های گم‌شده از شما بپرسد.

اگر دستیار گفت `denied`، بدون توکن اجرا شده است: گام ۳ را تکرار کنید و Claude Code را دوباره باز کنید.

## گام ۵. کارهایی که دستیار اجازه ندارد (و چطور ببینید)

- نمی‌تواند تأیید یا منتشر کند: وقتی توکن دستیار تنظیم شده، `brand:approve` و `brand:publish` اجرا نمی‌شوند.
- نمی‌تواند توکن بسازد، فهرست کند یا باطل کند: این دستورها رمز تأیید شما را می‌خواهند.
- بیرون از پروفایلش را نمی‌خواند؛ مقادیر محرمانه به شکل `withheld` (پنهان) برمی‌گردند.

یک محدودیت صادقانه: دستیاری که اجازه دارد هر دستوری را روی کامپیوتر شما اجرا کند، می‌تواند خودش پوشهٔ `brand/.private/` را باز کند.
به دستیار اجازه ندهید آن پوشه را بخواند یا `brand:agent-token`، `brand:approve` یا `brand:publish` را اجرا کند. وقتی Claude Code برای این کار اجازه خواست، «نه» بگویید.

## گام ۶. خاموش کردن دستیار (باطل کردن توکن)

دیدن توکن‌ها:

<div dir="ltr">

```sh
npm run -s brand:agent-token -- list < brand/.private/approval-secret
```

</div>

باطل کردن یک توکن با شناسه‌اش (با `agt_` شروع می‌شود):

<div dir="ltr">

```sh
npm run -s brand:agent-token -- revoke --id agt_… < brand/.private/approval-secret
claude mcp remove brand-os --scope local
```

</div>

سپس Claude Code را ببندید و دوباره باز کنید. توکن باطل‌شده از دفعهٔ بعدی که سرور روشن شود کار نمی‌کند؛ به حالت مهمان
برنمی‌گردد، بلکه اصلاً روشن نمی‌شود.

اگر ممکن است توکن جایی لو رفته باشد (مثلاً جایی چسبانده‌اید)، همان لحظه باطلش کنید و توکن تازه بسازید.

## برنامه‌های دیگر: Claude Desktop، Cowork، ChatGPT، Grok، Claude Projects

- **Claude Desktop یا Cowork** می‌توانند همین سرور محلی را روشن کنند. یک ورودی `brand-os` با توکن در `env` آن اضافه کنید
  (نمونه در [AI_CONNECTORS.md](AI_CONNECTORS.md#claude-desktop--cowork-via-local-mcp)): در مخزن برند
  `node /path/to/brand/.brand-os/engine/brand-os.mjs mcp` و در قالب `npm run -s mcp:serve`.
- **ChatGPT، Grok یا Claude.ai Projects** نمی‌توانند آن را روشن کنند. یک بستهٔ فقط‌خواندنی صادر کنید و فایل‌هایش را به‌عنوان
  دانش پروژه بارگذاری کنید:

<div dir="ltr">

```sh
npm run brand:pack -- --profile content-read --lang fa
```

</div>

این بسته فقط زمینهٔ تأییدشده دارد؛ بارگذاری آن، آن را با آن محصول به اشتراک می‌گذارد؛ و کهنه می‌شود: بعد از هر تأیید
دوباره صادر کنید.

## عادت‌های خوب

- برای هر دستیار و هر کار یک توکن جدا. دستیار دوم توکن دوم می‌گیرد؛ دسترسی یک توکن را بزرگ نکنید.
- کوچک‌ترین پروفایل را انتخاب کنید. فهرست کامل پروفایل‌ها در [AI_CONNECTORS.md](AI_CONNECTORS.md#profiles) است.
- توکن‌هایی را که دیگر لازم ندارید باطل کنید (`list` نشان می‌دهد `active` است یا `revoked`).
- هر خواندن دستیار در `brand/.private/access-log.jsonl` ثبت می‌شود، بدون خود مقادیر.

## وقتی چیزی درست کار نمی‌کند

| چه می‌بینید | یعنی چه | چه کنید |
|---|---|---|
| `Approval proof rejected` | رمز درست نبود یا در پوشهٔ اشتباه هستید. | ترمینال را در پوشهٔ برند باز کنید و دستور را تکرار کنید. |
| `… was revoked. Refusing to start.` یا `… does not match an issued token` | توکن باطل شده یا اشتباه کپی شده است. | توکن تازه بسازید (گام ۲) و دوباره وصل کنید (گام ۳). |
| در همهٔ پاسخ‌ها `denied` | سرور بدون توکن روشن شده است. | گام ۳ را تکرار کنید و Claude Code را دوباره باز کنید. |
| `refuses to run while BRAND_OS_AGENT_TOKEN is set` | دستور مالک را در ترمینالی اجرا کرده‌اید که توکن دستیار در آن است. | یک ترمینال تازه باز کنید و دوباره اجرا کنید. |
| `has more than one hard link` یا `appears to be synced by Google Drive` | پوشهٔ برند داخل پوشه‌ای است که با فضای ابری همگام می‌شود و رمز تأیید شما را بارگذاری می‌کند. | پوشه را جابه‌جا کنید (مثلاً به `~/Code`)، `npm run brand:doctor -- --fix-links` و سپس `npm run brand:doctor -- --rotate-approval-secret` را اجرا کنید. |

چیزهای زیادی برای تأیید دارید؟ `npm run brand:pending -- --lang fa` همه را به زبان ساده فهرست می‌کند و یک دستور برای
تأیید همه با یک بار وارد کردن رمز نشان می‌دهد. دستیار هرگز آن را به‌جای شما اجرا نمی‌کند.
